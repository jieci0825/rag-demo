# rag 流程

## step1-数据索引阶段
> 所谓数据索引，就是将文档存储到向量数据库的过程

1. 加载文档: 
这一步很简单，通过不同的文档加载器即可

2. 切分为 chunks: 通常的切分策略有两种: 

  1. 根据语义进行切割: 更侧重语义完整性，按照句子的粒度切割，将每一段文本按照句号、问号、叹号等标点符号切割

  2. 根据固定长度切割: 即每 n 个字符为一段

  > 这两种不是对立的，而是可以混合使用的。
3. 转为向量嵌入: 通常是通过一些 ai 嵌入模型实现

4. 存入向量数据库: 选择一款合适的向量存储数据库即可

## step2-检索前处理

> 这一步的目的就是为后面的检索和检索后处理做必要的准备，以便提高检索阶段召回知识的精确度与最终生成的质量

1. 查询转换（Query Rewriting）: 将用户的原始问题，重写为一个更加清晰、更标准、检索更友好的表达方式，例如：

   | 原始问题                     | 转换后                           |
   | ---------------------------- | -------------------------------- |
   | 这个 APP 支不支持退款？      | APP 退款政策是什么？             |
   | 我买的耳机怎么一直没有声音？ | 耳机无声音的常见原因及其解决方法 |


2. 查询扩充（Query Expansion）: 在不改变用户意图的前提下，**添加相关词语或同义表达**，让检索系统能够匹配更多语义相关的文档。这个操作可以显著提高**召回率**。

   | 原始提问题 | 扩充后                                   |
   | ---------- | ---------------------------------------- |
   | 项目合同   | [项目合同，合作协议，法律文件，合同模板] |

3. 检索路由（Retrieval Routing）: 在准备外挂知识库的时候，往往会有多个语料库。针对不同类型的问题，选择不同的知识库或者不同的检索方式，实现多路检索策略，例如：

   | 原始问题                     | 路由策略说明                             |
   | ---------------------------- | ---------------------------------------- |
   | 这款产品电池容量是多少？     | 路由到【产品参数知识库】                 |
   | 怎么退货？                   | 路由到【客服 FAQ 知识库】                |
   | 能在详细说明一下工作原理吗？ | 路由到【技术文档知识库】，或使用多路检索 |


## step3-检索操作
检索阶段分为下面几个步骤：
1. 将 query 转化为向量

2. 在向量数据库中进行相似度检索
   1. 余弦相似度：关注向量方向是否一致
   2. 欧式距离：衡量向量之间的绝对距离远近
   3. 点积：综合体现方向一致性与向量大小（长度）

## step4-检索后处理
即使使用了很优秀的向量搜索，检索回来的 Top-k chunks 仍然会存在一下问题：
1. 内容相关性差：向量相似度高但语义上与用户问题不匹配
2. 信息冗余：多个 chunks 说的是同一件事，浪费词元空间
3. 有害内容：包含过时、不合法、敏感内容
4. 结构混乱：拼接后的上下文缺少逻辑、排序不合用户意图

针对上面可能出现的问题，有一些常见的处理：
1. 重排序（Reranking）
2. 过滤无关内容（Filtering）
3. 合并去重（Merging）
4. 精简摘要（Summarization）
5. 格式优化（Structuring）

## step5-答案生成
将检索的结果和问题一起发给 LLM
